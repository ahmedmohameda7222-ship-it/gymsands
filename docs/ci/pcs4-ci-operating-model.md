# PCS-4 CI Operating Model

## Purpose

PCS-4 establishes a durable CI operating model that gives ordinary Draft pull requests fast, risk-scoped feedback without weakening the exact-head release authorities used for phase closure and Production release.

PCS-4A is the approved and merged implementation of this operating model. It was squash-merged through PR #130 as `main@ac65a8b61e051756628992ec151288d6b47bfef2` after Phase A run `30970963453`, PR Quality run `30970963310`, and canonical Quality run `30971418928` passed on exact reviewed head `1bdba5f441a88d722444667acacf591930d94416`.

## PCS-4A Draft PR validation authority

`.github/workflows/pr-quality.yml` is the single automatic path-scoped PR validation authority. `scripts/ci-change-scope.mjs` classifies the exact PR diff and emits the existing lane outputs plus four rendered-suite outputs:

- `rendered_general`
- `rendered_train`
- `rendered_active_workout`
- `rendered_workout_history`

The workflow keeps exact PR-head checkout, PR-number concurrency with cancellation, fail-closed classification, bounded failure artifacts, and stable job/check names.

## Lane matrix

| Lane / check name | Selection | Authority |
|---|---|---|
| `scope` | Always | Exact diff classification and scope summary |
| `integrity` | Always | Exact head/base identity, `git diff --check`, clean tracked tree |
| `core` | Every non-document change | Lint, typecheck, and complete unit suite |
| `database` | Database, integration, central CI, dependency, or fallback risk | Migration replay, database lint, verification SQL, ledger, integration tests |
| `ui-and-i18n` | At least one rendered output | One mock-auth build, one production server, selected rendered suites |
| `ci-contracts` | Workflow, scripts, toolchain, or fallback risk | Repository script and telemetry contracts |
| `build` | Runtime, rendered, build-authority, dependency, or fallback risk | Production environment contract and non-mock production build |
| `dependency-audit` | Dependency metadata changed | Runtime dependency audit |
| `required-summary` | Always | Required aggregate result |

Documentation-only changes run `scope`, `integrity`, and `required-summary` without reinstalling the application.

## Rendered-suite selection

A bounded Workout History implementation change selects only Workout History rendered QA. A bounded Active Workout implementation change selects only Active Workout rendered QA. A bounded Train implementation change selects only Train rendered QA. Mixed domain changes combine those booleans by union.

Shared app layouts and boundaries, `components/layout/**`, `components/ui/**`, global styles or theme authority, Tailwind or PostCSS configuration, messages, public assets, the general rendered runner, and central PR workflow/selector authority select all rendered suites conservatively.

Test-only paths do not activate rendered QA merely because they live beside UI implementation code. Any selected rendered output implies `ui=true`, `core=true`, and `build=true`.

The `ui-and-i18n` job does not repeat unit subsets already covered by `npm run test:unit`. It installs Chromium, builds the mock-auth QA application once, starts one production server, waits once, runs only the selected explicit suites, stops the server safely, and uploads only evidence generated by selected suites.

## Fail-closed unknown-path policy

Empty diffs and unknown non-document execution paths remain fail-closed. Unknown runtime or UI authority selects all rendered suites and the existing broad safe lanes. New paths must not silently bypass validation.

## Stable check identity

The required PR check names remain:

- `scope`
- `integrity`
- `core`
- `database`
- `ui-and-i18n`
- `ci-contracts`
- `build`
- `dependency-audit`
- `required-summary`

PCS-4A does not rename these checks.

## Authority boundaries

| Stage | Purpose |
|---|---|
| Draft PR Quality | Automatic path-scoped feedback on each PR head |
| Canonical phase-close Quality | Complete exact-head release validation after the stable Draft is explicitly marked Ready for review |
| Exact Release | Reuses and verifies the existing canonical Quality artifact and runs read-only release preflight |
| Release preflight | Fails closed on identity, compatibility, ledger, artifact, or authorization mismatch |
| Deployment | Provider action after approved merge or other explicit release authority |
| Production verification | Independent proof of deployed identity, health, browser behavior, errors, and retained evidence |

A passing Draft PR Quality run is not phase closure or release authorization. Canonical phase-close Quality remains mandatory for final phase closure.

`.github/workflows/phase-a-diff-validation.yml` remains unchanged. Repository-level branch protection and required-check provider enforcement were evaluated and deliberately deferred because the repository currently has one active owner and no delivery team. That decision does not weaken the repository-owned PR Quality, canonical Quality, Exact Release, or release-preflight authorities. Provider controls must be reconsidered before adding collaborators, delegating merges, or increasing repository access risk.

## Closure

PCS-4 is complete. The durable scope is the PCS-4A path-scoped Draft PR validation authority plus the existing exact-head phase-close and release authorities. No application runtime, database, migration, dependency, deployment, or Production behavior was changed by PCS-4. PCS-5 Production Foundation is next.

## Runtime measurements

No CI duration SLA or pass/fail runtime budget is approved. Workflow durations are informational until an explicit budget decision is recorded.
